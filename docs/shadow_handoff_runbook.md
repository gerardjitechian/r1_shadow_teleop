## Purpose

This runbook explains what to do with the Shadow print-only bundle generated on the R1 machine.

The purpose is to validate the **handoff boundary** between:

```text
R1 ROS 2 machine
```

and:

```text
Shadow ROS 1 laptop/container
```

This test confirms that the Shadow side can read and understand the command packet generated by the R1 side.

This is a dry-run handoff document only. It is not the future live bridge or
physical publishing procedure. Guarded live publishing should be documented
separately when that later phase is implemented.

---

## What You Are Testing

You are testing:

```text
R1-generated JSON command packet
        ↓
Shadow-side Python reader
        ↓
validation of joint names and positions
        ↓
print-only ROS 1 JointTrajectory preview
```

Expected target topic:

```text
/rh_trajectory_controller/command
```

Expected command shape:

```text
JointTrajectory
  joint_names: 12 Shadow joint names
  points[0].positions: 12 positions in the same order
  points[0].time_from_start: duration
```

---

## What You Are Not Testing

You are **not** testing physical robot motion yet.

You are **not** publishing to:

```text
/rh_trajectory_controller/command
```

You are **not** enabling live teleoperation yet.

You are **not** enabling force feedback.

## Step 1: Copy Bundle from USB to Shadow Laptop

On the Shadow laptop, copy the bundle from USB to the home directory.

Example destination:

```text
~/shadow_print_only_bundle_<timestamp>.tar.gz
```

Then confirm:

```bash
ls -lh ~/shadow_print_only_bundle_*.tar.gz
```

---

## Step 2: Unpack and Test Outside Docker

On the Shadow laptop:

```bash
mkdir -p ~/shadow_print_only_test

tar -xzf ~/shadow_print_only_bundle_*.tar.gz -C ~/shadow_print_only_test

cd ~/shadow_print_only_test/r1_shadow_teleop

python3 tools/shadow_ros1_sender.py   --packet runtime_data/shadow_hand/latest_command_packet.json
```

Expected ending:

```text
Not publishing because --publish was not provided.
```

This means the script read the packet and stayed in print-only mode.

---

## Step 3: Test Safety Refusal Outside Docker

Still outside Docker:

```bash
python3 tools/shadow_ros1_sender.py   --packet runtime_data/shadow_hand/latest_command_packet.json   --publish   --i-understand-this-can-move-the-robot
```

Expected ending:

```text
Refusing to publish: packet safety flags do not allow robot motion.
Required: safety.publish_to_robot=true and safety.dry_run_only=false
```

This refusal is a success.

It means the sender script will not publish current dry-run packets even if publishing flags are passed.

## Step 4: Copy Into Shadow Docker Container

Check container name:

```bash
docker ps --format 'table {{.Names}}	{{.Image}}	{{.Status}}'
```

Expected container name:

```text
dexterous_hand_real_hw
```

Copy the unpacked test folder into the container:

```bash
docker cp ~/shadow_print_only_test/r1_shadow_teleop   dexterous_hand_real_hw:/tmp/r1_shadow_teleop_print_test
```

Enter the container:

```bash
docker exec -it dexterous_hand_real_hw bash
```

## Success Criteria

This Shadow handoff test is successful if all of the following happen:

- The bundle unpacks on the Shadow laptop.
- The script reads `runtime_data/shadow_hand/latest_command_packet.json`.
- The script prints the Shadow `JointTrajectory` preview.
- The printed joint names are exactly:

  ```text
  rh_FFJ1
  rh_FFJ2
  rh_FFJ3
  rh_FFJ4
  rh_RFJ1
  rh_RFJ2
  rh_RFJ3
  rh_RFJ4
  rh_THJ1
  rh_THJ2
  rh_THJ4
  rh_THJ5
  ```

- The one-shot test ends with:

  ```text
  Not publishing because --publish was not provided.
  ```

- The safety test ends with:

  ```text
  Refusing to publish: packet safety flags do not allow robot motion.
  ```

## Failure Cases

### Bundle not found

Check where the USB mounted and copy the `.tar.gz` to the home directory.

### Python cannot find the packet

Confirm:

```bash
ls -lh runtime_data/shadow_hand/latest_command_packet.json
```

Run from:

```text
~/shadow_print_only_test/r1_shadow_teleop
```

or inside Docker:

```text
/tmp/r1_shadow_teleop_print_test
```

### Docker container name differs

Run:

```bash
docker ps --format 'table {{.Names}}	{{.Image}}	{{.Status}}'
```

Use the actual name instead of `dexterous_hand_real_hw`.

### Script refuses due to safety flags

That is expected for current packets.

### Script refuses due to joint names

Stop and inspect. The Shadow joint set may differ from the discovered configuration, or the packet may be stale/wrong.
